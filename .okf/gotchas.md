# Gotchas

- **Root `Cargo.toml` is generated.** Treat it as read-only; edit per-crate `Cargo.toml` files instead (`README.md`).
- **Always `-p <crate>`.** Full-workspace `cargo build` / `test` is slow and discouraged for routine work.
- **Binary name mismatch:** cargo produces `xai-grok-pager`; product/install name is `grok`.
- **DotSlash required for hermetic protoc.** Without `dotslash` on `PATH`, `bin/protoc` cannot download; builds needing protoc fail obscurely.
- **No raw canonicalize.** Use `dunce::canonicalize` (or tools `util::fs` helpers). Std/tokio canonicalize yields Windows `\\?\` paths that break git and path equality; clippy bans the raw APIs.
- **User home vs project `.grok`.** `$GROK_HOME`/`~/.grok` is user-global; project-local `.grok` is not a fallback for user home resolution.
- **Config secrets in parse errors.** Never log full TOML `Display` errors; use redacting helpers in `xai-grok-config`.
- **Config precedence is not CLI, env, `config.toml`, then managed.** Highest first: CLI, direct env, `requirements.toml` / MDM (clamps), `GROK_CONFIG` overlay, `config.toml`, `managed_config.toml`, defaults. See [Operations](operations.md#config-and-observability).
- **Responses SSE heartbeats:** `xai-grok-sampler/src/client.rs` filters `keepalive` (SSE event name or JSON `type`) before async-openai decoding. Heartbeats must not terminate the stream or count as model output; unrelated unknown events and malformed response payloads remain errors. Regression: `cargo test -p xai-grok-sampler --lib responses_stream_skips_keepalive_and_preserves_errors`.
- **Credential telemetry:** `SamplingClient::post` and subagent model-resolution logs report key presence only. Never log bearer or API-key prefixes, including for short tokens; `post_never_logs_credential_fragments` captures emitted tracing fields with synthetic credentials. A pinned Codex subagent must retain the ChatGPT bearer resolver attached by `sampling_config_for_model`; the session-token resolver applies only when no provider resolver exists. ChatGPT provider refresh and 401 recovery match the live route as well as the model ID to avoid minting a ChatGPT token for a colliding wire ID.
- **Responses tool-call reconciliation:** Match argument frames to output items by item ID when available. On `response.incomplete`, a newly recovered call requires a terminal item or arguments-done frame before tool execution, while snapshot calls preserve existing length-policy behavior. Regressions: `cargo test -p xai-grok-sampler --lib stream::responses::tests`. Recovered SSE maps are bounded by model output and frame count, except content-index gaps (bounded to 64).
- **MCP reqwest skew.** MCP crate intentionally uses reqwest 0.13; do not “fix” by unifying versions without understanding the quarantine.
- **MCP tools are hidden from sampling by default.** Schemas stay behind `search_tool` / `use_tool` for KV-cache stability. Opt in with per-server `promote_tools` (bare or `server__tool` names). Project `.grok/config.toml` lists count only when folder trust allows project scope (`project_scope_allowed`); an untrusted repo must not promote a user-scoped MCP tool. Do not re-enable full MCP tool lists in the prepare path without a config allowlist.
- **third_party is vendored upstream source**, not app code. Re-apply `VENDORING NOTES` patches on upgrade; British `LICENCE` filenames are intentional.
- **External PRs are not accepted** (`CONTRIBUTING.md`). Do not design workflows around community contribution.
- **Sandbox default is off.** Tests or demos that assume confinement must set `--sandbox` / config explicitly. Under workspace/read-only/strict, kernel write-deny still blocks agent writes to `~/.grok/config.toml`. User settings persist (`/settings`, `/model`, permission toggles) goes through `xai-grok-sandbox` `user_config_writer` (re-exec of the current binary, detached from the terminal process group, before bwrap/Seatbelt; do not `libc::fork` it from the tokio runtime). `xai-grok-pager-bin` `main` must call `run_user_config_helper_if_requested` before threads. The helper requires a 32-byte token (process memory after adopt). The token crosses the bwrap re-exec only inside a pipe (`GROK_USER_CONFIG_WRITE_TOKEN_FD`); it must not be an environment value because `/proc/<pid>/environ` keeps the initial block after `remove_var`. Adopt reads and closes that pipe before tools run. CLOEXEC is not the auth boundary: a same-uid child can still dup the socket via `/proc/<pid>/fd`. It also refuses a `config.toml` symlink that resolves outside grok home. Do not drop `config.toml` from the write-deny list to “fix” settings; that reopens H1-3969489. Folder trust (`trusted_folders.toml`) remains session-only under those profiles.
- **`/purge` does not follow symlinks.** `clear_directory_contents` refuses a symlinked `sessions/` or `logs/` directory and unlinks symlink entries without following them. Do not switch that sweep back to `exists` / `is_dir` / `remove_dir_all` on the raw path.
- **Sunset sandbox settings persist:** fork-only privileged `config.toml` writer. On sync, drop the area and take `main` if upstream lands the same (or equivalent) persist path. Do not merge our helper with theirs. Details: [Fork Sync → Sunset: sandbox settings persist](fork-sync.md#sunset-sandbox-settings-persist).
- **Clippy config does not merge.** Nearest `clippy.toml` wins; codegen-oriented bans live at repo root for this tree.
- **release vs release-dist vs release-local.** Local `--release` is not the hardened dist profile; shipping uses `release-dist`. Local install script uses `release-local` (faster: no LTO, CGU=8, no debug).
- **SOURCE_REV** identifies monorepo provenance; it is not a crates.io version by itself.
- **Fork branch model:** `main` is a pure upstream mirror (`origin/main`); local customizations live only on `dev`. When `origin/main` advances, follow [Fork Sync](fork-sync.md) (ff `main`, rebase `dev`, force-with-lease push `dev` only after confirm). Do not put custom commits on `main`.
- **Always-keep fork files:** never take upstream (or auto-merged) content for `crates/codegen/xai-grok-agent/templates/prompt.md`, `subagent_prompt.md`, or root `README.md`. On every fork sync, restore all three from the pre-sync `dev` backup branch even if git reported no conflict. Details: [Fork Sync](fork-sync.md#always-keep-fork-files).
- **Prompt template update flow:** edit `templates/*.md` → `python3 scripts/encrypt_templates.py` (from `xai-grok-agent`) → fix `prompt::template` / `prompt::context` tests → fold into the existing `customize system prompts` commit. Do not hand-edit `src/prompt/prompt_encrypted.rs`. Full steps: [Workflows → System prompt templates](workflows.md#system-prompt-templates).
- **OKF ownership:** only the `setup okf` area commit may change `.okf/**` (and root `AGENTS.md` when it is the OKF gate). Feature commits stay product/code only; fold any docs updates into `setup okf` (fixup + autosquash). Mixing OKF into later areas causes fold/rebase conflicts on `workflows.md` and friends.
- **Fork features: thin switchboards.** New `dev` work should live in fork-owned modules with 1-2 registration touch points in shared upstream files. Do not add fields to multi-site structs or grow `effects/mod.rs` / `persistence.rs` with large bodies. Rules: [Conventions](conventions.md#fork-customizations-dev-only).
- **ChatGPT Codex:** do not send a Grok session bearer to chatgpt.com. Codex entries must `has_own_credentials()` (synthetic `auth_provider.chatgpt`). First-party Responses extras (`reasoning.encrypted_content`, hosted search includes) are gated in `agent/chatgpt/extras.rs`; Codex 400s on unknown `include` values. Codex also 400s on `role: system` in `input` ("System messages are not allowed"); extras stamps `responses_system_as_instructions` and `apply_response_defaults` lifts those items into the top-level `instructions` field (Codex CLI's shape). Do not drop the Grok system prompt. OAuth client id `app_EMoamEEZ73f0CkXaXp7hrann` is unofficial; do not spoof a Codex User-Agent without an explicit decision. Callback port 1455 clashes with OpenCode/Codex CLI (`--device` fallback). Remote prefetch *replaces* the default map; `chatgpt::merge_catalog` must run after that assign or `gpt-6-astra` / `gpt-6-sol` vanish from `/model`. Astra reasoning: `xhigh`/`high`/`medium` (default)/`low`. Sol also advertises `max`. Do not offer `none` (Codex HTTP 400). Those lists are what `/model` shows after picking a Codex model. Seeded overrides are bare keys (`[model.gpt-6-astra]`, `[model.gpt-6-sol]`).
- **ChatGPT / quota tests are not on slim defaults.** Feature sets and filters: [Testing](testing.md#chatgpt-regression-checks). A default-feature compile error there is a missing feature, not a product bug. Production `cargo check -p xai-grok-pager` needs none of those features.
- **ChatGPT quota:** `wham/usage` is an unofficial subscription endpoint, not OpenAI API billing. Never reuse Grok auth or log response bodies. Optional windows do not imply zero usage. Alt+Q and prompt rendering both use `quotaProvider` metadata; unknown providers must not fall back to Grok. ChatGPT cache is app-owned and identity/request-scoped, separate from agent-local Grok balance and `/usage`. Account identity is read from the local ChatGPT credential store, matching the local-shell login flow.
- **ChatGPT Codex hotspots:** `default_model_entries`, `resolve_model_list` (`merge_catalog` after prefetch), and `sampling_config_for_model` in `agent/config.rs`; extras stamps on `SamplerConfig` (`include_encrypted_reasoning`, `responses_system_as_instructions`) applied in `apply_response_defaults`. Feature body stays in `agent/chatgpt/` plus the lift helper in sampling-types `responses.rs`. Codex `response.completed` can arrive with empty or partial `output` after text / function-call frames already streamed. Sampler `StreamedOutput` reconciles output-item identities, content indexes, and call IDs before flattening the response. Do not materialize `content_index` holes (`MAX_RECONCILED_CONTENT_PARTS`). Live session and subagent turns reattach ChatGPT credentials through `stamp_reconstructed_sampler_config` (provider name, not only the Codex URL). Do not replace that with global text concatenation or an all-or-nothing tool-call fallback: partial snapshots can otherwise lose calls or duplicate earlier text.
- **Fork overrides: filter, do not delete main’s assembly.** For UX/policy on values main still builds (e.g. hide `always-approve` on the prompt info line), leave hot paths like `agent_view/render.rs` matching main and filter in fork-owned code (`credit_bar::keep_info_line_mode_flag`, `PromptBorderChips`). Deleting upstream pushes/branches is a recurring rebase tax.
- **Sunset gix 0.86:** fork pins workspace `gix` above `main` until `main` is `>= 0.86` (gix-odb cleared-slot panic). Dedicated series area, last in the stack. On sync, drop the area when `main` catches up. Do not fold into slim. Details: [Fork Sync → Sunset: gix 0.86](fork-sync.md#sunset-gix-086-gix-odb-2723).
